## Summary

Slice 7 adds `links v1`, a layer that appends Definition-punishment links to the ranked output of the Frozen rule. A murder query matches the definition (IPC 300) while the punishment sits in IPC 302, and a search for criminal breach of trust returns IPC 406 and not the defining IPC 405. The spec proposed fixing both through the Cross-reference graph, but the data refutes that: the graph has 615 edges (586 resolved) and no edge between 302 and 300, 406 and 405, or 420 and 415. The links are implicit, because the punishing section uses a defined term and not a section number. ADR 0007 records this and the rule that replaces it.

What changed, by ticket (all seven are done):

- Ticket 1: a test pins the missing edges and the 615/586 edge counts, so a later change to `xref.py` fails loudly. ADR 0007 is new.
- Ticket 2: `ibid links list` derives IPC links. A section headed "Punishment for X" is linked both ways to every other top-level section whose heading equals X after lowercasing and stripping the trailing full stop. No fuzzy or substring match.
- Ticket 3: the same command carries each IPC link to the BNS through verified Concordance v3 entries only, checked against the pin.
- Ticket 4: `ibid links expand` reads a baseline predictions file and writes a `links v1` file. Originals stay first and in order, partners follow, and the baseline hash is recorded. It covers top-k (k=5) and threshold (r=0.7) on both Acts.
- Ticket 5: `links v1` is scored once per Multi-charge set and Act, and `results/layer-comparison.md` shows it beside the Baseline with mean predictions per item.
- Ticket 6: `ibid links bench` scores `links v1` once on the ILSI test split with the existing micro-F1, with its own ledger.
- Ticket 7: `.scratch/slice-7/report.md`, generated by `report.py`, applies the decision rule.

Decision-rule outcome: NEGATIVE. The owner chose the per set and Act reading (D-002). `links v1` finds more charges on set v1 IPC (8 to 10), set v1 BNS (9 to 11) and set v2 IPC (9 to 17), and the same number on set v2 BNS (13 to 13), so the rule, which needs a rise everywhere, fails. ILSI test micro-F1 rises from 9.37 to 11.37 (top-k) and from 9.64 to 11.81 (threshold). The links module stays as a documented dead end and nothing is wired into the MCP server.

Review follow-ups folded in: the test that called `links.expand` directly was deleted (ordering and no-duplicates are covered through `ibid links expand`), the bench compare test now runs `ibid charges compare` and asserts on rendered rows, `links.py` has one shared `_pairs` helper for IPC and BNS, and `CONTEXT.md` gained the Definition-punishment link term.

No contradiction with an ADR. Expansion runs after ranking and takes no model, so ADR 0001 holds.
