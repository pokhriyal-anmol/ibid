# Q-006: Which keyword figure the `search` tool text quotes

Status: pending
Slug: slice-11
Raised by: wf-build, ticket 3 (measured limits in tool descriptions)
Blocking: no
Reversible: yes

## Question

Spec decision 7 says the `search` description and caveat state that keyword search "finds about 5 percent of charges on story-style queries". Ticket 3 asks for the per-set IPC baseline figures from `results/layer-comparison.md` instead, citing D-002, and notes you may choose different wording. Which should a client read?

## Why only you

This is what the tool tells its users about itself, and D-002 covers keep-or-drop rules, not product wording, so neither the spec nor a standing decision settles it.

## Options

1. Per-set IPC ranges (the build's default): "3.1 to 5.1 percent of IPC charges on set v1 and 4.8 to 6.0 percent on set v2". Every number is a row in the results file and the test checks each one, but the text is longer and names test sets a client does not know.
2. The spec's single "about 5 percent". Short and plain, but it is a pooled figure that is in no row of the results file, so the test can only check that it sits inside the per-set range.
3. A rounded range, for example "3 to 6 percent of IPC charges". Plain, and still checkable against the rows, but it drops the set names and the BNS figures (up to 9.9 percent).

## Default taken

Option 1. `KEYWORD_LIMITS` in `src/ibid/mcp.py` quotes the per-set IPC ranges, and `expected()` in `tests/test_mcp_limits.py` builds the same text from the baseline rows of `results/layer-comparison.md`. `.scratch/slice-11/pr.md` states the deviation from the spec's wording.

## If you answer differently

Change the `KEYWORD_LIMITS` string in `src/ibid/mcp.py` and the `expected()` builder in `tests/test_mcp_limits.py`, rerun that test once against a wrong figure, and align spec decision 7 and the `pr.md` line. No scores, pins or `PARSER_VERSION` change.
