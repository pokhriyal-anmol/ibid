# Q-007: Which output rule of the frozen rule is scored on ILSIC

Status: pending
Slug: slice-14
Raised by: wf-build, ticket 1 (ilsic eval for the frozen rule)
Blocking: no
Reversible: yes

## Question

The frozen rule v2.11 has two output rules: top-k (k = 5) and a relative threshold (sections scoring at least 0.7 of the top score). The spec does not say which one is scored on ILSIC. The build scored the threshold output only. Which do you want?

## Why only you

D-002 says a rule must name its comparison level before any score, the spec does not name this one, and the frozen-rule ILSIC scores now exist, so choosing the reading now is post-hoc.

## Options

1. Threshold output only (the build's default). One frozen-rule row per test set, `output_rule: "threshold"` in the results file.
2. Top-k output only (k = 5). One row per test set; precision likely lower, recall likely higher.
3. Both output rules, two frozen-rule rows per test set, in line with D-002 counting both output rules. Costs a second look per split for the frozen rule under a new ledger key.

## Default taken

Option 1, in `src/ibid/ilsic.py` (`"output_rule": "threshold"`). The frozen rule is below every published ILSIC number on both test sets under this reading.

## If you answer differently

Option 2 or 3: add the top-k output to the frozen-rule path in `src/ibid/ilsic.py` with a test, score the frozen rule on the Lay and Multi tests (with `--rescore-test` for option 2, or a separate ledger key per output rule for option 3), and regenerate `results/ilsic-report.md`. The other layers are not touched.
