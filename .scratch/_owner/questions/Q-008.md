# Q-008: How BNSS headings are verified when the Gazette has no Arrangement of Sections

Status: pending
Slug: slice-15
Raised by: wf-build, ticket 3 (BNSS parse and heading check) and ticket 6 (concordance tripwire); wf-review (finding "BNSS headings not checked against a second source at the 98% floor")
Blocking: no
Reversible: yes

## Question

Spec decision 4 promised that each Act's headings are checked against its own Arrangement of Sections at a 98% floor. The PRS Gazette copy of the BNSS prints no Arrangement, only margin notes. The build read BNSS headings from the margin notes, checked the count against the published 531, and checked headings only for presence, so the 98% floor is met without testing anything. The only independent heading check left for the BNSS is the 80% tripwire against the CAPT table subjects (now 89.5%, 475 of 531). Review then amended spec decisions 4 and 7 to state this as a "BNSS exception" rather than add a second source. Do you accept that, or do you want a real second-source heading check for the BNSS?

## Why only you

The 98% bar was set before measuring and the spec was then amended after the gap was found, which is the post-hoc change D-002 and D-004 leave to you, and it decides how strongly the claims ledger may say BNSS headings are verified.

## Options

1. Accept the exception (the build's default). BNSS headings are margin notes, checked by count and presence and by the 80% CAPT tripwire. `docs/claims.md` must say the BNSS headings are not matched against an independent list at 98%.
2. Fetch a second BNSS source that prints an Arrangement of Sections (for example the Bill as passed, or an India Code copy) and run the 98% check against it, as for the CrPC. Needs a new download you approve (D-007 covers only the three slice-15 sources) and a new test.
3. Raise the CAPT-table cross-check for the BNSS from a tripwire to a quality bar (for example 90%), accepting that the table paraphrases. It already measures 89.5%, so this needs a loosened comparison or fails.

## Default taken

Option 1. Spec decisions 4 and 7 and ADR 0010 state the BNSS exception; the real-file heading test requires 531/531 present and prints that no Arrangement exists; the invented fixture does carry an Arrangement, so the dropped-section and changed-heading tests still fail on known-bad input. The gap is listed in `.scratch/slice-15/pr.md`.

## If you answer differently

Option 2: download and pin the second source, add a 98% heading-match test against it, record the source in the spec and ADR 0010, and rewrite the BNSS check-results row in `docs/claims.md` (pinned by `tests/test_claims.py`). Option 3: change the floor in the concordance tripwire test, rerun its known-bad check, and update `docs/claims.md`, `.scratch/slice-15/report.md` and spec decision 5. No index, pin or `BNSS_PARSER_VERSION` change in any case unless option 2 finds heading errors.
