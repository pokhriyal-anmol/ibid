# Q-002: Training data and section threshold for assoc-nb v2

Status: pending
Slug: slice-6
Raised by: proxy-approve, ticket 2 (assoc fit on ILSIC-Lay); spec decisions 1 and 2
Blocking: no
Reversible: yes

## Question

`assoc-nb v2` is fitted on the ILSIC-Lay train split alone (6,465 layperson posts), with a vocabulary of IPC sections that occur in at least 5 train posts (98 sections, 27 of set v2's 30). Do you want that, or should ILSI judgment text be added to the training data, or a different threshold used?

## Why only you

The spec records both as defaults the owner has never been asked about, and the choice decides what the layer is meant to learn from.

## Options

1. Keep the default: ILSIC-Lay train only, `--min-posts 5`. The layer learns layperson wording only; 3 of set v2's sections stay outside the vocabulary.
2. Add ILSI fact text to the ILSIC-Lay train posts, threshold 5. More sections reach the threshold, but court wording is mixed back into a layer meant for layperson text, and ADR 0006 must cover both sources.
3. ILSIC-Lay train only with a lower threshold (for example 2 or 3). More of set v2's sections are nameable, but sections with very few posts get noisy term counts.

## Default taken

Option 1. Ticket 2 built `ibid assoc fit --source ilsic-lay ... --min-posts 5`, and ticket 6 fitted and scored `assoc-nb v2` once per set and Act with those inputs.

## If you answer differently

Both are CLI inputs, so no code changes for option 3: refit, call it a new layer version (v3), score it once per set and Act, and regenerate the comparison and the ticket 7 report. Option 2 also needs the fit to accept two sources at once (a code change in `src/ibid/assoc.py`) and an ADR 0006 amendment.
